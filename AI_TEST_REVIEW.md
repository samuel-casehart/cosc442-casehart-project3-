    Overall the quality of the tests was pretty good. The original generated tests had nearly complete statement and branch coverage, testing edge cases, etc. The only minor miss was on testing a middle spot which is understandable as it might decide testing a single middle spot is necessary rather than all of them. Even without prompting guides, the AIwas able to setup all test in the Arrange,act, assert style as taught in class. 

    A big improvement that the AI made that I might carry over to my own creation of tests is the division of tests into different classes. For example, the AI decided to group all tests involving Stocking into one nested class, while all tests for removal into another. I also had AI review my original tests and it found that some were redundant as well as named in ways that didn't really properly describe what they were doing. These reviews proved true as I looked through my own code once again at the areas it highlighted. When I conducted a review of the AI's code however, I found only a single redundant test and the names of the tests accurately described what it was testing. 

    My takeaway from this excercise is that AI can be used in two ways. The first is to write the tests yourself then have AI highlight possible problem areas for your review, to help speed up that part of the process. The second way is to have AI generate the code itself, and then have a person review the code. I think that the first option is the best, as I suspect that AI will continue to have trouble with full generation of code, when compared to reviewing something that has already been produced.
